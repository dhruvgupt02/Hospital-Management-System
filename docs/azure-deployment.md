## 2. DP-900 Service Mapping & Relational Concepts

### A. Azure Database for PostgreSQL Flexible Server
- **Core Relational Storage**: Hosts transactional OLTP tables (`appointments`, `medical_records`, `invoices`, `payments`).
- **PostgreSQL Extension Support**: MediCare leverages `btree_gist` for GiST-indexed range exclusion constraints. Azure Flexible Server natively supports `btree_gist` through server parameter configuration (`azure.extensions = 'btree_gist'`).
- **High Availability**: Zone-redundant high availability with automatic failover across Azure Availability Zones.

### B. Azure SQL Database (Relational Mapping & Differences)
If deploying onto Azure SQL Database (T-SQL engine) rather than PostgreSQL:
- **Exclusion Constraints**: T-SQL lacks native `EXCLUDE USING gist` range constraints. To achieve equivalent zero-race collision prevention, Azure SQL requires an `INSTEAD OF INSERT/UPDATE` trigger with `SERIALIZABLE` transaction isolation or an explicit table locking pattern (`WITH (TABLOCKX)`).
- **Temporal Tables**: Azure SQL provides native System-Versioned Temporal Tables (`PERIOD FOR SYSTEM_TIME`), which can automatically track historical medical record versions.

### C. Azure Blob Storage (Document & Lab Report Vault)
- **Private Hot/Cool Tiers**: Laboratory PDF reports and radiographic scans are stored in private storage containers (`medical-records-private`).
- **Time-Limited Access**: Files are accessed via Shared Access Signatures (SAS) generated by the Django backend with a 15-minute expiration time, preventing persistent unauthorized hotlinking.

### D. Azure Key Vault
- Eliminates hardcoded credentials and `.env` files in cloud production.
- Database passwords and cryptographic JWT signing keys are retrieved at runtime via Azure Managed Identity (`DefaultAzureCredential`).

### E. Azure Monitor & Application Insights
- **APM Telemetry**: Automatically records HTTP response codes, end-to-end request durations, database query latencies, and exception stack traces.
- **Alerting Rules**: Pre-configured alerts fire if HTTP 5xx errors exceed 1% or if appointment conflict rates spike anomalously.

### F. Microsoft Entra ID (Azure AD) SSO Roadmap
- Staff users (Doctors, Receptionists, Billing Staff, Admins) can authenticate using OpenID Connect (OIDC) through corporate Entra ID tenants with conditional access and multi-factor authentication (MFA).

## 3. Step-by-Step Deployment Guide (Azure Container Apps)

### Step 1: Resource Group & Managed Database
```bash
az group create --name rg-medicare-prod --location eastus

az postgres flexible-server create \
  --resource-group rg-medicare-prod \
  --name psql-medicare-prod \
  --admin-user medicareadmin \
  --admin-password 'YourSecureP@ssw0rd!' \
  --sku-name Standard_B2s \
  --tier Burstable \
  --version 16

az postgres flexible-server parameter set \
  --resource-group rg-medicare-prod \
  --server-name psql-medicare-prod \
  --name azure.extensions \
  --value btree_gist
```

### Step 2: Private Storage Account
```bash
az storage account create \
  --name stmedicareprod \
  --resource-group rg-medicare-prod \
  --location eastus \
  --sku Standard_LRS \
  --allow-blob-public-access false

az storage container create \
  --account-name stmedicareprod \
  --name medical-records-private \
  --auth-mode login
```

### Step 3: Deploy to Azure Container Apps
```bash
az containerapp create \
  --name app-medicare-backend \
  --resource-group rg-medicare-prod \
  --environment env-medicare-prod \
  --image medicare-backend:latest \
  --target-port 8000 \
  --ingress external \
  --env-vars \
    DB_NAME=medicare_db \
    DB_HOST=psql-medicare-prod.postgres.database.azure.com \
    DB_USER=medicareadmin \
    DB_PASSWORD=secretref:db-password
```
